# 第 3 章 标注开源代码

## 3.1 怎么标

四个层级分别对应四类对象，写法各不相同：

| 层级 | 对象 | 写法 | 本次处数 |
| --- | --- | --- | --- |
| 类 | 顶层类型 | 类声明前用 `/** */`，讲这个类在系统里站什么位置 | 2 |
| 方法 | 对外或关键方法 | Javadoc，摘要加 `@param` / `@return` | 2 |
| 代码块 | 一段连续语句 | 块首用 `/* */`，讲这段在保证什么 | 2 |
| 语句 | 单条语句 | 行前用 `//`，一行讲清为什么是这句 | 3 |

一条原则：只写读代码看不出来的东西。方法名已经说明用途的，不再复述；改坏了会出事的地方，必须写。

## 3.4 标注后的检查

改完核对过三件事：

1. 只动注释。`git diff --stat` 是 6 个文件、+32 行 / −8 行，删除的 8 行是两处英文注释被改写；把新增行里以 `*`、`/*`、`//` 开头的滤掉后为空，说明没混进代码。
2. 不叠注释。目标位置上方若已有注释块，采取改写而不是再加一段，避免同一处出现中英两段说明。第 3、5 号两处的原文是英文简注，内容与本次标注讲的是同一件事，直接改写成中文并补足原因，语义没有丢。
3. 能编译。`assembleDebug` 通过，产物 `MiCodeNotes-debug.apk` 1.1 MB，注释没有影响构建。

表 3-1 里的行号是标注完成后重新查的。之后如果代码有改动导致行号漂移，按"文件 + 对象"定位，不必按行号硬找。
