# 小组协作说明

仓库地址：https://github.com/kamten7/Notes-master

## 第一次拿代码

装好 Git 之后先把身份配上，不然提交记录显示的是别人的名字：

```bash
git config --global user.name "你的名字"
git config --global user.email "你的邮箱"
```

然后克隆，路径别带中文和空格：

```bash
git clone https://github.com/kamten7/Notes-master.git
```

Android Studio 打开克隆下来的目录，等 Gradle Sync 跑完。第一次会下载 AGP 依赖，慢的话是网络问题，
工程里已经配了阿里云镜像和腾讯的 Gradle 镜像，正常情况不用再改。

## 分支怎么用

三个人直接往 main 推肯定会撞。一人一个分支，做完再合并：

```bash
git checkout main
git pull                     # 先同步，别在旧代码上改
git checkout -b feature/lock  # 建自己的分支
```

改完提交：

```bash
git status                   # 看看改了哪些文件
git diff                     # 看看具体改了什么
git add 具体文件              # 不要 git add . 一把梭
git commit -m "feat: 锁定后禁止编辑便签"
git push -u origin feature/lock
```

推上去以后在 GitHub 页面点 Compare & pull request，组长看完合并到 main。
不想走 PR 也行，至少先 `git pull --rebase` 再推。

## 冲突

两个人改到同一个文件的同一段才会冲突。核心文件（`NotesProvider.java`、
`NotesDatabaseHelper.java`）尽量只让一个人动。

冲突时 `git pull --rebase`，打开文件把 `<<<<<<<`、`=======`、`>>>>>>>` 之间的内容
按需要保留，删掉这些标记，然后 `git add 文件`、`git rebase --continue`。

## 提交之前

```bash
gradlew.bat assembleDebug
```

编译过了再提交。推不过去的代码，最后合并的时候会更麻烦。

## 分工参考

| 人 | 分支 | 负责 |
| --- | --- | --- |
| 组长 | main | 合并、整合、报告定稿 |
| A | feature/lock | 便签锁定：数据列、编辑页菜单、列表标记 |
| B | feature/tags | 便签标签：设置对话框、列表显示、按标签筛选 |
| C | feature/sort | 列表排序，以及第 3 章的四级标注（要改注释） |

## 交报告的分工栏怎么写

按实际干的活写，别三个人都写“全栈开发”。谁画了图、谁跑的静态分析、谁写的标注，
报告里对应的表格和截图就是谁出的，被问到要能讲清楚自己那部分是怎么做的。
