# 小组协作说明（Git + GitHub）

远程仓库：https://github.com/kamten7/Notes-master

## 一、每个人第一次拉代码

1. 安装 Git（Windows 版即可），在命令行确认：
   ```
   git --version
   ```
2. 配置自己的身份（必须用自己的名字，提交记录才认得出是谁做的）：
   ```
   git config --global user.name "你的名字"
   git config --global user.email "你的邮箱"
   ```
3. 克隆仓库（建议放在不含中文和空格的路径）：
   ```
   git clone https://github.com/kamten7/Notes-master.git
   ```
4. 用 Android Studio 打开克隆下来的 `Notes-master` 目录，等 Gradle Sync 完成。

## 二、日常开发流程（推荐分支 + 合并请求）

不要三个人直接往 main 上推，容易互相覆盖。统一用「一个人一个分支」：

```
# 1. 每次开始前先同步主干
git checkout main
git pull

# 2. 建自己的分支，名字用拼音或学号，例如：
git checkout -b feature/lock-chen

# 3. 改代码，改完看状态
git status
git diff

# 4. 提交（一次只提交一件事，信息写清楚）
git add 具体文件路径
git commit -m "feat: 便签锁定后禁止编辑"

# 5. 推到远程自己的分支
git push -u origin feature/lock-chen
```

推上去之后在 GitHub 网页上点 **Compare & pull request**，由组长合并到 main。
如果不想用 PR，至少也要先 `git pull` 再推，避免冲突。

## 三、分支划分建议（3 人）

| 成员 | 分支 | 负责内容 |
| --- | --- | --- |
| 组长 | main（只做合并） | 整合、发版、报告定稿 |
| 成员 A | feature/lock | 便签锁定（数据列、编辑页、列表标记） |
| 成员 B | feature/tags | 便签标签（设置、显示、筛选） |
| 成员 C | feature/sort | 列表排序 + 第 3 章四级标注 |

## 四、冲突处理

- 两个人改到同一个文件的同一区域才会冲突，尽量按文件分工：`NotesProvider.java`、`NotesDatabaseHelper.java` 这类核心文件指定一个人改。
- 出现冲突时：
  ```
  git pull --rebase
  ```
  打开冲突文件，保留需要的代码，删除 `<<<<<<<`、`=======`、`>>>>>>>` 标记，然后
  ```
  git add 冲突文件
  git rebase --continue
  ```

## 五、提交前自检

```
gradlew.bat assembleDebug
```

能编译通过再提交，不要把编译不过的代码推到远程。

## 六、用 WorkBuddy 的注意事项

- WorkBuddy 可以直接读写本机文件、执行 `git` 命令，所以可以让它帮忙改代码、查编译错误、写文档。
- 但**提交记录必须是真实的**：谁在什么时候提交、改了什么，都要对得上。指导书第 4、5 条明确要求数据真实、禁止抄袭，编造提交记录一旦被核对（时间和代码状态对不上）按抄袭处理。
- 建议每个人自己动手跑一次环境搭建并保留报错截图，这部分是指导书明确要求的「全员参与、过程留痕」，别人替代不了。
