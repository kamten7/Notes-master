# 实施计划

按《软件工程》实验指导书的评分表倒排，把参考工程的交付物逐项拆成我们自己的任务。
原则：结构和版式可以照它的思路来，但图、数据、截图、报告正文必须自己产出，
尤其是表 1-1 的行数、方法数这类数字，两边一样就说不清了。

## 一、交付物对照

参考工程做到这些，我们一项项对齐：

| 它有什么 | 我们要做的 | 数量 | 负责人 |
| --- | --- | --- | --- |

## 二、步骤和顺序

有依赖关系，顺序错了要返工：

**第 0 步（今天）：先做"维护前"的基线**

第 5 章要维护前后对比，必须有一份原始版本的截图。现在代码已经改过了，所以要单独搭一份：

```bash
# 复制原始源码到独立目录，不要动仓库
xcopy /E /I D:\cxdownload\源程序代码-小米便签-Notes-master\Notes-master D:\cxdownload\Notes-baseline

# 把构建配置拷过去（只拷配置文件，不拷 src）
copy D:\cxdownload\Notes-maintain\build.gradle D:\cxdownload\Notes-baseline\
copy D:\cxdownload\Notes-maintain\settings.gradle D:\cxdownload\Notes-baseline\
copy D:\cxdownload\Notes-maintain\gradle.properties D:\cxdownload\Notes-baseline\
copy D:\cxdownload\Notes-maintain\lint.xml D:\cxdownload\Notes-baseline\
copy D:\cxdownload\Notes-maintain\local.properties D:\cxdownload\Notes-baseline\
xcopy /E /I D:\cxdownload\Notes-maintain\gradle D:\cxdownload\Notes-baseline\gradle
copy D:\cxdownload\Notes-maintain\gradlew D:\cxdownload\Notes-baseline\
copy D:\cxdownload\Notes-maintain\gradlew.bat D:\cxdownload\Notes-baseline\
```

这份基线会卡在 `setLatestEventInfo` 编译错误上（新 SDK 删了这个方法），要先把
`GTaskASyncTask` 里的通知改成 `Notification.Builder` 才能编译。这一步单独说明一句就行：
"为在编译环境里跑通基线，先做了通知接口的适配，不涉及界面和行为"。

装上之后截：列表页、编辑页、编辑页菜单、设置页，共 4 张，命名 `baseline-01` 到 `baseline-04`。

**第 1 步（并行，1 天）：三章各做各的**

- A 画图、统计表 1-1、表 1-2
- B 跑静态分析、写人工分析
- C 做四级标注（要改代码，建议单独分支，最后再合，避免和功能分支撞）

**第 2 步（0.5 天）：第 4 章文字**

把已经做完的改动写成"需求分析 → 影响范围 → 设计 → 编码 → 测试"这条链。
每处改动都要回答：为什么要改、会影响哪些类、为什么不选另一种方案、怎么验证的。

**第 3 步（0.5 天）：第 5 章**

用第 0 步的基线截图 + 新版本截图做对比，每个功能按"操作 → 结果"写。

**第 4 步（0.5 天）：第 6 章 + 汇总**

心得各自写，不能一个人代写三个人。最后统一图表编号、目录、封面分工。

## 四、每项怎么算做完

- 图：有源文件（`.puml` 或 `.mdj`）和导出的 png，图里类名和代码一致
- 表 1-1：能用一个命令或脚本复现出同样的数字
- 静态分析：报告里有文件名、行号，能点开对照
- 标注：`git diff` 能看出改的是注释，不是逻辑
- 截图：状态栏时间、电量不一样，不能是同一张图改的
- 报告：图表编号连续，目录页码对得上，封面分工和实际提交对得上

## 五、容易出问题的地方

1. **表 1-1 的数字**：随手写会被问"怎么统计的"。要么写脚本，要么说明白是 `find` + `wc -l` 数出来的。
2. **第 3 章标注改代码**：别在功能分支上改，最后合并容易冲突。C 单独一个分支，先合。
3. **截图重复**：三个人用同一台模拟器截，列表里的便签内容会一模一样。各自建几条不同的便签再截。
4. **报告和代码对不上**：报告里写的类名、方法名、菜单文字，必须和代码里一致（我们菜单是英文 `Lock note`、`Tags`，报告里别写成中文）。
5. **提交时间**：三个人都在最后一天提交会被看出来。按上面的顺序，一人一天，自然就行。
